# 汇出档 → Dashboard

客户接不到会计软体，但拿得出报表汇出档时走这条。产出跟直连路线**完全一样的**
`dashboard-data.json`，所以 `render-dashboard.mjs`、`headless-check.mjs`、
`suggest.mjs`、`build-site.mjs` 一行都不用改。

## 第 0 步 — 先确认装好了没

这条路线是**独立入口**：使用者说「我没有会计软体」就会直接进来，可能什么都还没装。
先找，找不到就装，**不要假设 `finance-dashboard-setup` 跑过**。

```bash
DASH=$(dirname "$(find ~ -name render-dashboard.mjs -not -path '*/node_modules/*' 2>/dev/null | head -1)")
echo "${DASH:-NOT-INSTALLED}"; node -v 2>/dev/null || echo "no-node"
```

**找到了** → 记下 `$DASH`，进第 1 步。

**没找到 / 没有 node** → 一步一步装：

1. **Node.js** —— 没有的话弹出选项：我帮你装 / 我自己装（nodejs.org）/ 这是什么。
   ⚠️ Windows 装完要**重开终端机**，环境变数才生效。
2. **複製管线** —— 把这个 skill 的 `assets/` 整个複製到工作目录
   （预设 `~/FinanceDashboard`，Windows 是 `%USERPROFILE%\FinanceDashboard`）。
3. **装相依** —— 读 Excel 需要一个套件：
   ```bash
   cd "$DASH" && npm install
   ```
   直连路线不需要这步，只有读档要。
4. **建设定档** —— 複製 `profile.example.json` 成 `profile.json`，填公司名，
   并把 `system` 设成 `file-import`。

⚠️ **除了作业系统，不要问其他技术问题。** 会走到这条路线的人已经说了「没有会计软体」——
再问他 API、问他资料库在哪、问他用哪套软体，一题都不适用，只会让他觉得走错门。

`$DASH` 是变数不是字面路径，每个人装的位置不一样。

## ⚠️ 铁律一：一律要问「账期几天」

**只要资料来源是汇出档（不是直连），就必须问使用者：应收账期和应付账期各是几天。
不准跳过、不准假设 30 天。**

原因不是麻烦，是**帐龄表根本不知道答案**：

会计软体的 Debtor / Creditor Aging Report 是按「**距开票日几个月**」分桶的 ——
`CURRENT`、`1 MONTH`、`2 MONTHS` … `11 & OVER`。它**没有到期日、没有信用期**。

所以「1 MONTH」那一桶到底算不算逾期，完全取决于账期：

| 账期 | 「1 MONTH」桶的真实状态 |
|---|---|
| 30 天 | 刚过期，算逾期 |
| 60 天 | **还没到期**，不算逾期 |
| 90 天 | 离到期还很远 |

**把「1 MONTH」一律当逾期，账期 60 天的公司逾期金额会凭空多一大截** ——
而且是那种「看起来很合理」的错：老板会开始催根本还没到期的客户。

### 怎么问

用 AskUserQuestion，两题（应收、应付分开问，很多公司不一样）：

- 常见选项：30 天 / 60 天 / 90 天 / **每个客户不同**
- 「每个客户不同」→ 问主要客户群用哪个，其余照那个算，**并在页面标注这是近似值**
- 「不知道」→ **不准猜**。请他问会计，或改成只显示未清余额、不分逾期桶

拿到之后写进 `profile.json`：

```json
{ "creditTermDays": { "ar": 60, "ap": 30 } }
```

⚠️ 页面上要写清楚「逾期以账期 N 天推算」。这是推算不是事实，读的人有权知道。

## ⚠️ 铁律二：GL 和明细帐不要收 PDF

- **Excel / CSV** → 可以
- **PDF** → 只能给损益表、资产负债表这种「人眼看几个数字来对帐」的用途

PDF 是**版面**不是资料。实测把客户的 Debtor Aging PDF 抽出来是这样：

```
10 MONTHS BALANCE11 & OVER8 MONTHS 9 MONTHS6 MONTHS 7 MONTHS5 MONTHS...
```

栏序被打散、数字与标题黏在一起。硬解析出来的数字**不会报错**，图照样画得漂亮。

**帐龄表也要 Excel**，理由同上。

## ⚠️ 铁律三：科目分类一定要用眼睛确认过

汇出档只有科目**编号**和**名称**，没有 AutoCount 那种 `AccType`。所以要靠编号前缀
判断哪些是收入、哪些是成本 —— **而这个对照每家公司都不一样，猜错就是收入变成本**。

实测案例：某公司的 `8xxx` 是 **OTHER INCOME**（佣金收入、汇兑收益、银行利息），
但一个「看起来合理」的通用预设把 8xxx 当成费用。照那样跑，收入会被算进成本，
损益表整个翻掉 —— **而且不会报错**。

### 做法：弹出选项，其中一个是「AI 自己判断」

用 AskUserQuestion 问，选项至少要有：

| 选项 | 做什么 |
|---|---|
| **AI 自己判断** | 你把**全部**损益科目名读完（不是只看前几个），做出分类，
然后**把判断和理由讲出来**，并**明确列出你判断不了的**再问一次 |
| 用某个已验证的 preset | 例如 `sql-accounting` |
| 我先看完整科目表 | 印出全部科目编号+名称让使用者自己决定 |
| 我自己指定 | 逐个前缀问 |

⚠️ **「AI 自己判断」不等于「AI 静默决定」。** 判断完一定要：

1. **列出分类结果和理由**（例如「8xxx 是其他收入，因为里面是佣金、汇兑、利息、股息」）
2. **主动指出可疑之处**，不要吞掉

实测：某公司的佣金收入同时出现在 `5301-5303`（营业收入）和 `8C01-*`（其他收入），
名称几乎一样。可能是换过科目、可能是两种收入、也可能是重复入帐 —— **三种的营收差很多**，
所以要问，不能自己挑一个。

### 前缀不够用：名称例外要先比对

同一个前缀里常常混了不同性质的科目。实测 `5xxx`（营业收入）里就有：

| 科目 | 该归 | 理由 |
|---|---|---|
| GAIN ON DISPOSAL OF ASSET | 其他收入 | **卖一台相机不是营业额。**留在 Sales 会让卖资产看起来像业绩成长 |
| GAIN ON FOREIGN EXCHANGE | 其他收入 | 汇兑收益算成营收是 `accounting-pitfalls.md` 第 4 个坑 |
| DISCOUNT ALLOWED / RETURN INWARDS | 营收**减项** | 折让和退货是扣减，不是收入 |

`ledger-map.json` 的 `classifyOverrides` 就是放这些的，**比对顺序在前缀之前**。

⚠️ **`ledger-map.json` 刻意不提供会自动套用的预设。** 只有具名 preset
（例如 `sql-accounting`），而且要明确选用。宁可多问一题，不要静默算错。

### 已验证的 preset

**`sql-accounting`**（eStream 标准科目表，实测过）：

| 前缀 | 分类 | 进哪一条损益线 |
|---|---|---|
| `1xxx` | 股本权益 | 资产负债表 |
| `2xxx` | 固定资产 | 资产负债表 |
| `3xxx` | 应收/其他应收 | 资产负债表 |
| `4xxx` | 应付/其他应付 | 资产负债表 |
| `5xxx` | **营业收入** | Sales |
| `6xxx` `7xxx` | **销货成本** | Cost of sales |
| `8xxx` | **其他收入** | Other income |
| `9xxx` | **营业费用** | Operating expenses |
| `SSTx` | 税务科目 | 资产负债表 |

**AutoCount 不需要这个** —— 它的科目自带 `AccType`（SL/OI/CO/EP），直接用就好。

## 步骤

### 1. 先看结构，不算数字

```bash
cd "$DASH" && node inspect-ledger.mjs /path/to/*.xlsx
```

它只回报：工作表、栏位对应、科目段数、交易列数、期间、科目前缀分布，
以及缺了哪些关键栏位。**不印客户名和金额** —— 那是别人的真帐。

对不上就改 `ledger-map.json`（见下），**不要改程式**。

### 2. 栏位对应：改 JSON，不改程式

`ledger-map.json` 是一份**可编辑的字典**，列出每个栏位可能的写法：

```json
"debit": ["debit", "dr", "借方", "借"],
"dueDate": ["due date", "due", "到期日", "到期"]
```

学员的档案写「Dr Amount」而不是「Debit」？加进阵列就好。
比对规则：**去空白、不分大小写、开头相符、最长的赢**（所以 `due date` 不会被 `date` 吃掉）。

### 3. 产生资料并验证

```bash
cd "$DASH" && node build-data-file.mjs /path/to/exports/ && node render-dashboard.mjs && node headless-check.mjs
```

### 4. 对帐（不可跳过）

拿客户自己的 **P&L** 和 **Balance Sheet** 核对。汇入路线的黄金验证是：

**总帐的借方总额必须等于贷方总额。** 对不上就是解析漏了或重复了，不要往下做。

## 这类汇出档的四个陷阱（实测踩过）

### ① 报表版面，不是表格

汇出的是「报表列印成 Excel」：报表页首 → 每个科目一段（`Account Code:` + 科目号 + 名称）
→ 栏位标题列 → `BALANCE B/F` → 交易 → 小计。要**按段落解析**，不是抓一次表头。

### ② 标题栏号 ≠ 资料栏号

合并储存格造成的。实测：`Debit` 标题在第 31 栏，数字在第 28 栏 ——
**照标题栏号去读会读到空格，而空格会被当成 0**。

解法：**先把合并储存格摊平**（区块内每一格都填上该区块的值），标题与数字的栏号才会重合。
`read-ledger.mjs` 的 `readGrid()` 就做这件事。

### ③ 一笔交易占好几列

垂直合并造成。照读会**每个金额都翻倍**。

解法：从合并清单取出「延续列」并跳过。**不要用「跟上一列长得一样就跳过」** ——
同一天两笔一模一样的分录在帐上很正常，那样会安静地删掉一笔真交易。

### ④ 日期差一天

Excel 日期用 `cellDates` 读会带进本机时区，**同一个档在 UTC+8 和 UTC+9 读出不同日期**。
实测 31 Dec 被读成 30 Dec。月初的交易会掉到上个月，月度数字全错。

解法：**读原始序号**（不用 `cellDates`），用固定公式转。学员机器时区不同也不会变。

## 汇入路线本来就有的限制，要先讲

| 项目 | 状况 |
|---|---|
| **新鲜度** | 只有上次汇出那么新。每日自动刷新用不上，变成「丢新档 → 重跑」 |
| **逐张单据未清** | 明细帐通常只有余额，没有逐张未清 → 催收清单只能到客户层级 |
| **逾期天数** | 靠账期推算（见铁律一），不是事实 |
| **栏位改版** | 会计软体升级后标题会变，然后**静默**解析出半张空表 → 每次都要先跑 `inspect-ledger.mjs` |
