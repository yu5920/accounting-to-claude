# 分析产品 / GP by Project

## 先找到工作目录

这个 skill 里的 `$DASH` 和 `$MCP` 是变数，不是字面路径 —— 每个客户装的位置不一样。

```bash
DASH=$(dirname "$(find ~ -name dashboard-data.json -not -path '*/node_modules/*' 2>/dev/null | head -1)")
MCP=$(cd "$DASH/../mcp-server" 2>/dev/null && pwd)
echo "dashboard: $DASH"; echo "mcp-server: $MCP"
```

找不到就代表还没建过 —— 改用 `finance-dashboard-setup` skill 从头做。
公司名、帐本、系统类型都记在 `$DASH/profile.json` 里。


Dashboard 左侧「分析产品」主题**预设是空的**。它由 `project-map.json` 驱动，
档案空着就整块留白 —— 这是刻意的诚实预设，不是 bug。

工作目录 `$DASH`

## ⚠️ 开始之前：这件事为什么不能自动做

**按营收比例分摊共用成本，在数学上必然让每个产品的毛利率等于公司整体毛利率。**

不是「大概会接近」，是**恒等式**：如果成本 C 按营收 Rᵢ/R 分给产品 i，
那产品 i 的毛利率 = (Rᵢ − C·Rᵢ/R) / Rᵢ = 1 − C/R = 公司毛利率。**跟 i 无关。**

所以一张「每个产品毛利率都是 23.4%」的表，看起来很精确，实际上一个字的资讯都没有 ——
它只是把公司毛利率抄了 N 遍。用它来决定「砍掉哪条产品线」会直接做错决策。

**这就是为什么这个流程一定要问，不准替使用者决定。**

## 执行方式：一题一题问，不准跳过

⚠️ **必须用 AskUserQuestion 弹出选项问**，不要用文字问、不要自己假设、
**更不要因为「资料不足」就默默跳过**。使用者有权知道有这个选项存在、以及不做的代价。

### 第 1 题 — 要不要做

先跑下面的「盘点」拿到真实数字，把「可直接归属占比」算出来再问。

用 AskUserQuestion，四个选项：

| 选项 | 说明 |
|---|---|
| **只做直接归属**（多数情况推荐） | 只显示能明确归属的成本，共用成本单独列一行不分摊。诚实但不完整 —— 看得到哪条线直接成本重，看不到「真实全成本毛利」 |
| **做完整分摊** | 共用成本按营收比例分给各产品线。⚠️ 结果是每条线毛利率都一样，**这张表不能用来做取舍决策**，只能用来看营收结构 |
| **先不做，改去打标签**（治本） | 这个主题继续留白。改成在 AutoCount 记帐时就把成本分到对应科目/部门，累积几个月后再回来做。唯一能得到真实产品毛利的路 |
| **先跳过，之后再说** | 明确跳过，主题维持留白。**下次触发这个 skill 时要重新问，不要记住跳过的决定** |

⚠️ 第四个选项必须存在。使用者可以选择不做，但必须是**知情后主动选的**，不是被系统默默省略的。

### 第 2 题 — 产品线怎么切（选了做才问）

把**这家公司的**营收科目列出来（`list_accounts` 或从 `dashboard-data.json` 的
`revenueAccounts` 拿），问要怎么分组。

〔示例，非真实资料〕一家培训顾问公司可能长这样：

| 科目 | 名称 |
|---|---|
| `41xx` | 主力服务收入（可能有实体 / 线上等数个子科目） |
| `42xx` `44xx` | 附属收费（补考费、行政费…） |
| `43xx` | 另一条业务线的收入（例如顾问费） |
| `45xx` `46xx` `49xx` | 手续费 / 车马费 / 其他收入 / 银行利息 |
| `REFUND` | 退款（`SA`，营收减项） |

常见切法（用 AskUserQuestion 问，别自己选）：

- **两条线**：主力业务 ／ 另一条业务
- **多条线**：把大类再拆细（实体 / 线上 / 某专案 / 顾问），细到能对应成本科目为止
- **照科目原样**：每个营收科目自成一条线（不填 revenue 对照就是这个效果）

### 第 3 题 — 哪些成本算直接归属

**先自动盘点，再拿结果去问。** 有些公司的成本科目命名已经带产品线前缀
（`XX - 场地`、`XX - 教材` 这种），那是最省力的起点 —— 但**前缀是什么要从资料看，
不要假设**。先把成本科目名列出来找共同前缀：

```bash
cd "$DASH" && node -e '
const c=JSON.parse(require("fs").readFileSync("dashboard-data.json","utf8")).companies[0];
const tot=c.expenses.reduce((s,r)=>s+r.total,0);
// 抓出「XXX - YYY」这种命名里的前缀，按金额排
const g={};
for(const e of c.expenses){const m=/^([^-]{2,20})\s*-/.exec(e.name); if(!m)continue;
  const k=m[1].trim(); (g[k]=g[k]||{n:0,v:0}); g[k].n++; g[k].v+=e.total;}
for(const [k,v] of Object.entries(g).sort((a,b)=>b[1].v-a[1].v).slice(0,8))
  console.log(k.padEnd(22)+String(v.n).padStart(3)+" 个科目  "+Math.round(v.v).toLocaleString().padStart(11)+"  ("+(v.v/tot*100).toFixed(1)+"%)");
console.log("总成本费用 "+Math.round(tot).toLocaleString());'
```

〔示例结果〕某公司靠前缀可直接归属的成本约占总成本 **13%** —— 起点通常就是这个量级，
不要期待一开始就很高。

⚠️ **不要直接采用名称比对的结果，要拿去问。** 实测发现的陷阱：

〔示例〕有一组科目叫 `顾问服务 - 某某代理商`、`Lead Gen Service`、`SEO 顾问`，
名字里都有「顾问」，但那是**买进来**的行销服务（获客用），
**不是交付顾问业务的成本**。照字面归到顾问线，会让那条线毛利凭空少掉一大块。

**判准是钱的方向，不是科目名的字面。** 分不清就问：这笔钱是为了「把东西交付出去」
（归产品线），还是为了「把客人找进来」（多半是共用的获客成本）？

单一科目也可以拆成权重（例如租金 60/40 分给两条线），`project-map.json` 支援：

```json
"cost": { "6H07-R001": { "甲线": 60, "丙线": 40 } }
```

但**权重是拍脑袋来的**，除非有实际依据（坪数、人天、堂数），否则跟分摊一样没资讯。
要用就问清楚依据是什么，并写进 `_note`。

### 第 4 题 — 大额共用成本单独处理

`5104-01 Advertising Fees` 一个科目就 **980,000**，是最大单笔成本。
广告到底带来的是课程还是顾问的单，取决于投放内容 —— **问，不要猜**。

如果使用者知道大致比例（例如广告主要打课程），可以用权重拆。
不知道就留在共用池，别硬掰。

## 第 5 题 — 共用池里的**变动成本**，要不要一个一个分

⚠️ **这一步不准跳过，也不准自动做。必须弹出选项问。**

设完之后一定会剩一堆没归属的成本。但**变动和固定是两回事**：

- **变动成本没归属 = 真的漏了资讯。** 它随量发生，代表有东西驱动它 ——
  那个东西就是某条产品线。留在共用池等于把「钱跟着哪条线走」这件事藏起来。
- **固定成本没归属 = 通常是对的。** 租金、行政薪资本来就不属于任何单一产品线，
  硬编一个比例出来，就是把分摊问题换件衣服再做一次。

所以：**只针对变动成本走这个流程，固定成本预设留在共用池。**

```bash
cd "$DASH" && node allocate-costs.mjs
```

它会列出未归属科目，按变动/固定分开、依金额排序、并算**累计涵盖率** ——
因为重点是「处理前几大就够了」，不是把两百个科目全走一遍。

〔实测参考：某公司未归属变动成本 26 个科目共 158 万，但**前 5 大就涵盖 92%**，
所以实际只要问 5 题。〕

### 怎么问

**先问要不要做**，选项至少要有：

| 选项 | 说明 |
|---|---|
| 一个一个来（从最大的开始） | 我逐笔问，你决定归哪条线。前几大处理完就可以喊停 |
| 只处理前 N 大 | 讲清楚 N 笔涵盖多少 %，剩下的留共用 |
| 全部留在共用池 | 产品线只看直接成本。**这是合法选择**，不是偷懒 |
| 先解释给我听 | 讲变动 vs 固定的差别再决定 |

**答应了才开始逐笔问。** 每一笔的选项：

- 各条产品线（用 `project-map.json` 里实际有的线名，不要写死）
- **按比例拆**（要问依据是什么 —— 没依据的权重跟分摊一样没资讯）
- **留在共用池**
- **停，剩下的不分了** ← 这个选项每一题都要有，不能逼人走完

### 常见判断

- **广告费**通常是最大一笔变动成本。能不能拆，看投放有没有分产品线 ——
  **问，不要猜**。答不出来就留共用，那比乱拆诚实。
- **佣金**通常跟着成交的产品走，如果佣金制度是按产品算的，就拆得开。
- **行销部门薪资**被归成变动，是因为命中了 `MARKETING` 关键字 ——
  值得回头看它到底该不该算变动（见 `finance-dashboard-reconcile` 的成本分类段）。

## 写档

`project-map.json` 结构（`companies` 的 key 是 `build-data-cloud.mjs` 里的 `short`，
看 `$DASH/profile.json` 的 `books[].short`）：

```json
{
  "_revenueBasis": "recognised",
  "_sharedCostMethod": "revenue-share",
  "_note": "这里写清楚每个判断的依据和日期，下次才知道为什么这样分",
  "companies": {
    "<公司代号>": {
      "revenue": { "4101": "甲线", "4102": "甲线", "4103": "乙线", "4301": "丙线" },
      "cost":    { "5601": "甲线", "5801": "乙线", "6H07-R001": { "甲线": 60, "丙线": 40 } }
    }
  }
}
```

规则：

- `revenue` 没列到的营收科目 → **自成一条线**（用科目名称当线名）
- `cost` 没列到的成本科目 → **视为共用**
- `_sharedCostMethod` 决定共用成本怎么处理：
  - `"direct-only"` → **不分摊**，单独列「共用成本（未分摊）」一行
  - 其他值（含预设 `"revenue-share"`）→ 按各产品线营收比例分摊

⚠️ **`_sharedCostMethod` 原本是个装饰性栏位，`render-dashboard.mjs` 根本没读它** ——
不管填什么都照样分摊。已於 2026-08-19 补上实作（`projectRows()` 里的 `allocate` 判断）。
如果换了一份 `render-dashboard.mjs`，先确认这个栏位有没有被读，否则设定不会生效。

⚠️ 不分摊时产品线加总**不等于**公司损益，差额就是共用成本那一行。`viewProduct()` 会把
共用成本补进「营业合计」，所以合计仍与损益表相符 —— **验收时一定要对这个**。
〔实测案例：一家培训顾问公司 · AutoCount Cloud〕：营业合计 R 3,742,000 + 非营业收入 663 = 3,742,800 = 总览「已确认收入」。

改完重跑：

```bash
cd "$DASH" && ./daily-refresh.sh
```

⚠️ 只改 `project-map.json` 不用重抓 API —— 但 `daily-refresh.sh` 带 `--refresh` 会重抓。
只想快速看效果就跑 `node render-dashboard.mjs && node headless-check.mjs`。

## 验收

页面上「分析产品」主题会显示**直接归属成本占总成本的比例**。

**那个比例就是这张表可信度的上限。** 12.9% 意思是：87% 的成本是硬分的，
所以产品间的毛利差异有 87% 是分摊公式造出来的，不是真的。

**把那个数字推高的唯一办法不是改这个档案，是改记帐方式** ——
在 AutoCount 记成本时就分到对应科目或部门。

⚠️ 部门维度能不能用，看 `dashboard-data.json` 的 `deptCoverage`。
〔实测案例：一家培训顾问公司 · AutoCount Cloud〕是 `0 / 5,800` —— 完全没填，所以不能用。
要走部门这条路，得先在 AutoCount 记帐流程里开始填部门。

## 参考：一份填好的设定长什么样 〔示例，非真实资料〕

一家培训顾问公司切成四条线，`_sharedCostMethod: "direct-only"`：

| 产品线 | 营收科目 | 直接成本科目 |
|---|---|---|
| 甲线（实体交付） | `41xx` `42xx` `44xx` | 场地、教材、印刷等 `Course -` 前缀科目 |
| 乙线（线上交付） | `41xx` | 无（成本未分科目） |
| 丙线（某专案） | `41xx` | `58xx` 该专案专用科目 |
| 丁线（顾问） | `43xx` | 无 |

逐笔分配未归属**变动**成本时的几个判断：

- **广告费**（最大一笔）→ 帐上是每月一笔总额、看不出打哪条线。
  向使用者确认后归给主要招生的那条线；不确定就留共用。
- **佣金** → 跟着成交的产品走，看佣金制度怎么算。
- **代收代缴性质的费用**（政府基金、代垫）→ 归给对应的交付线。
- **部门薪资** → **不是变动成本**。它常因为科目名含部门关键字（MARKETING 之类）
  被误分成变动，要在 `cost-rules.json` 修，不是在这里分产品线。

⚠️ **某条线「100% 毛利」不代表它最赚钱**，只代表它的成本还没被标记。
讲给老板听的时候一定要带上这句。

⚠️ 退款科目（`SA` 类）若不在 `revenue` 对照里，会自成一条线。
知道退的是哪条线就把它对照过去。
